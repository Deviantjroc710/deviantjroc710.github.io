Backup and verification

The check passed every time. It was comparing the files against a copy of themselves, made seconds earlier.

How a check ends up unable to fail

The verifier compared the current tree against a baseline. The baseline was built as part of the same run. So a passing result meant the files matched a snapshot of those files taken moments before — which they always would, whatever had happened to them, however much had gone missing the week before.

Nothing about the output looked wrong. It printed a real comparison over real paths and returned a real, honest PASS. It just had no capacity to return anything else, which makes it decoration rather than a check.

Why this is easy to build and hard to notice

Whoever writes the fix usually writes the test for it, and does so with the fix fresh in mind — so the check ends up scoped to precisely what the fix touched. Both halves work exactly as intended. The gap only exists between them.

The tells are quiet ones. A baseline timestamped seconds before the run it validates. An expected-failures list that suddenly matches nothing. A verified scope that is identical to the set of files just rewritten.

The fix: a reference older than the thing it checks

The baseline is now rebuilt from version history at a known earlier point, about nineteen hours before the tree it compares against. That single property — the reference predates the subject — is what makes the result mean anything.

The verifier prints the baseline’s identity and age before it runs, and asserts the baseline is older than the tree. If it isn’t, it refuses rather than passing.

It now fails, and that’s the point

The current run reports two files missing and twenty-nine changed. Every one is accounted for in writing, because the baseline predates a day of deliberate work and those are exactly the files that day touched.

A FAIL that can be explained line by line is worth more than a PASS that could never have been anything else. The value of the check is not the result — it’s that the result was in doubt.

What it’s guarding

An automated backup that runs unattended and reports failures loudly, covering everything that would be painful to lose across a few machines. A restore has been rehearsed, because a backup nobody has restored from is a hypothesis.
